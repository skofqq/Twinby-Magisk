# Twinby AdBlock (Magisk)

Magisk-модуль, который блокирует рекламу в Android-приложении Twinby через systemless hosts:
домены рекламных SDK (Yandex Mobile Ads, myTarget, AdMob, AppLovin, Unity Ads, ironSource и др.)
резолвятся в `0.0.0.0`, и SDK не может загрузить объявление.

Работает с Magisk 20.4+, KernelSU и APatch.

## Установка

1. Соберите zip: `./build.sh` (или скачайте артефакт из GitHub Actions).
2. Magisk → Модули → Установить из хранилища → `out/twinby-adblock-<версия>.zip`.
3. Перезагрузите устройство и принудительно остановите Twinby, чтобы он забыл закешированные объявления.

Встроенный в Magisk модуль «Systemless hosts» и AdAway в режиме systemless тоже подменяют
`/system/etc/hosts`, поэтому одновременно с ними работает только один модуль. Установщик предупредит о конфликте.

## Что учитывать

- hosts действует на всё устройство: реклама этих SDK пропадёт и в других приложениях.
- Свои домены можно дописать в `/data/adb/twinby_adblock/custom.txt` (по одному на строку), они применятся после перезагрузки.
- Если включён «Частный DNS», hosts всё равно применяется: системный резолвер сначала смотрит в него.

## Списки

- `lists/ads.txt`: домены рекламных SDK.
- `lists/twinby.txt`: рекламные эндпоинты самого Twinby (пока пусто).

## Как найти рекламные домены Twinby

1. Поставьте [PCAPdroid](https://github.com/emanuele-f/PCAPdroid) и запишите трафик Twinby, пока показывается реклама.
2. Посмотрите, к каким хостам приложение обращается в момент показа баннера.
3. Добавьте рекламные хосты в `lists/twinby.txt` и пересоберите модуль.

Если реклама приходит с основного API Twinby (тот же домен, что и анкеты), hosts её не уберёт:
блокировка домена сломает само приложение. Тогда следующий шаг: LSPosed/Zygisk-модуль,
который перехватывает показ рекламы внутри процесса Twinby.
