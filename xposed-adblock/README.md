# Twinby AdBlock — Xposed-модуль

Убирает рекламу, которую hosts-модуль убрать не может: всплывающие вставки Yandex
(InterstitialAd/RewardedAd) и рекламный баннер в ленте анкет (рисуется нативным Yandex
SDK через плагин `flutter_yandex_ad`).

Работает только внутри процесса `com.twinby`, трогает лишь рекламные классы Yandex Ads —
анкеты, чат и сеть приложения не затрагиваются.

## Требования

- Телефон на arm64 с root (Magisk) и Xposed-фреймворком: LSPosed или Vector (JingMatrix).
  На x86-эмуляторе хук не работает: Twinby там идёт через ARM-трансляцию, а фреймворк
  перехватывает только нативные процессы.
- Twinby, установленный легально (из Play). Модуль не трогает лицензионную проверку.

## Сборка

Открыть папку `xposed-adblock/` в Android Studio и собрать APK
(`Build → Build APK`, или `./gradlew :app:assembleRelease`). Готовый файл:
`app/build/outputs/apk/release/app-release-unsigned.apk` (debug-сборка подписывается сама).

## Установка

1. Поставить собранный APK как обычное приложение.
2. В LSPosed/Vector включить модуль «Twinby AdBlock (hook)».
3. В скоупе модуля отметить **Twinby** (скоуп уже прописан в манифесте — `com.twinby`).
4. Принудительно остановить Twinby и открыть заново.

## Как проверить и доработать

Модуль пишет в лог (`logcat`, тег `TwinbyAdBlock`), какие рекламные классы Yandex он нашёл
и какие вызовы заблокировал. Если в конкретной сборке что-то называется иначе или баннер
остаётся, по этому логу хук правится точечно (имена классов в `TwinbyAdHook.java`).

Если окажется, что баннер в ленте — это промо самого Twinby с `api.twinby.com`
(ответ `/v1/ad/next`), а не Yandex-реклама, то Xposed до Flutter-слоя не достанет, и его
убирают фильтрацией этого ответа (локальный прокси), а не этим модулем.
