# Twinby sync-ad proxy (отдельный Magisk-модуль)

Убирает рекламную карточку в ленте анкет, которую hosts-модуль убрать не может:
её вставку решает сервер `twinby.ru` по пути `/sync-ad/...`. Локальный прокси
перехватывает только этот путь и отдаёт пустую рекламу. Остальной трафик Twinby
(анкеты, чат, фото) и другие приложения не затрагиваются.

Ставится **в дополнение** к hosts-модулю `twinby_adblock`, не заменяет его.

## Как работает

- `service.sh` при загрузке ставит systemless-доверенный CA (для Android ≤13 — в
  `/system/etc/security/cacerts`, для 14+ — bind-mount поверх conscrypt APEX),
  запускает прокси и через `iptables -m owner --uid-owner` заворачивает на него
  **только** исходящий 443 процесса `com.twinby`.
- `proxy/` (Go) расшифровывает только соединения с SNI `twinby.ru`; всё прочее
  (включая бакеты фото) туннелирует без расшифровки. На `/sync-ad` отдаёт
  содержимое `/data/adb/twinby_adblock/sync_ad_response.json` (по умолчанию
  `{"ads":[]}`), остальные запросы к `twinby.ru` проксирует как есть.
- Режим в `/data/adb/twinby_adblock/mode`: `passthrough` (ничего не режет — для
  проверки, что приложение работает) или `block` (включает фильтр `/sync-ad`).

## Сборка

`./proxy-module/build.sh` — сгенерирует CA (если нет своего в `proxy-module/ca/`),
соберёт arm64-бинарь прокси и упакует `out/twinby-syncad-proxy-*.zip`.
Нужны `go`, `openssl`, `zip`.

> ⚠️ Собранный zip содержит приватный ключ CA — это секрет вашего устройства.
> Не публикуйте готовый zip и не коммитьте `proxy-module/ca/`.

## Проверка и откат

Логи прокси: `/data/adb/twinby_adblock/proxy.out`. Для отката удалите модуль в
Magisk и перезагрузитесь — CA, прокси и правило iptables исчезают (`uninstall.sh`).
